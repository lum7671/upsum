# 로그 전처리 개선 계획

본 문서는 원본 로그 전처리 시 유실되는 핵심 정보를 보존하고, 불필요한 Git diff 상세 정보를 제거하여 Gemini 분석 및 요약 결과의 품질을 향상하기 위한 개선 계획을 정의합니다.

## 1. 개선 목표 및 세부 사항

| 번호 | 개선 영역 | 현재 상태 | 개선 목표 | 기대 효과 |
| :--- | :--- | :--- | :--- | :--- |
| **1** | **Homebrew 미브루 파일 복원** | `/usr/local/lib/`, `/usr/local/include/` 하위 경로 라인이 무조건 삭제되어 빈 헤더만 노출됨 | 해당 경로의 파일 목록 라인을 보존함 | Gemini가 관리자 조치 사항(Action Item)에 삭제 대상 파일을 구체적으로 명시할 수 있음 |
| **2** | **Git 업데이트 실패 요약 유지** | `ERROR: Failed to update...` 라인이 일괄 삭제되어 개별 저장소의 실패 여부를 추론에만 의존함 | `ERROR:`로 시작하는 요약 실패 라인을 보존함 | 저장소 업데이트 실패 목록을 직관적이고 정확하게 인식함 |
| **3** | **Git 상세 변경 파일(Diffstat) 제거** | 파일 목록(`README.md \| 9 +--`) 및 통계 정보가 그대로 유지되어 로그 용량의 약 30%를 차지함 | 파일 상세 변경 내역 및 `files changed` 요약 라인을 삭제함 | 토큰 소모를 줄이고 변경 레포지토리 정보에만 집중함 |
| **4** | **Podman 이미지 상태 보존** | `UNCHANGED` 라인이 지워져 각 컨테이너 이미지 풀 결과의 성공 여부 확인이 어려움 | `UNCHANGED` 또는 `UPDATED` 요약 결과를 인라인으로 유지함 | 이미지 변경 유무와 풀 상태의 흐름을 보존함 |
