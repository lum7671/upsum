# upsum 및 sumuplogs 아키텍처 고도화 작업 명세서 (고도화001)

본 문서는 `sysloadmon` 프로젝트의 모던한 아키텍처 패턴을 벤치마킹하여 `upsum` 및 `sumuplogs` 프로젝트에 적용한 대대적인 리팩토링 및 고도화 내역을 상세하게 정리한 기술 사양서입니다.

---

## 📌 1. 아키텍처 고도화 개요

### 1.1 배경 및 목적
기존의 `upsum` 및 `sumuplogs`는 각각 시스템 업데이트 요약 및 시스템 경고/에러 분석을 성공적으로 수행했으나, 설정 변수의 유효성 검증이 수동(`os.getenv` 및 수동 타입 캐스팅)으로 작성되어 번잡했고, Gemini API의 스키마 제어가 원시적인 JSON 스키마 명세서에 의존하여 안정적인 응답 획득에 제약이 있었습니다. 또한, 이메일 본문이 단순 마크다운 렌더링에 그쳐 시스템 관리자가 모니터링 리포트를 시각적으로 열람하기에 가시성이 다소 미흡했습니다. 
이에 따라 최신 프로젝트인 `sysloadmon`에서 검증된 아키텍처 기법을 도입하여 설정 파싱, 스키마 유효성 보장, 메일 전송 레이아웃을 현대화했습니다.

### 1.2 핵심 변경 사항 요약
1. **개발/빌드 환경 단일화**: Python 3.13.2 개발 버전 고정 및 빌드 시스템을 `uv_build`로 통일.
2. **선언형 설정 관리 (`pydantic-settings`)**: `.env` 및 환경 변수의 로드와 유효성 검증을 Pydantic으로 자동화.
3. **타입 안전한 구조적 생성 (`response_schema`)**: SDK 호출 시 Pydantic BaseModel을 스키마에 직접 바인딩하여 타입 안전성 확보.
4. **Jinja2 기반 Styled HTML 이메일**: 도메인 테마가 반영된 CSS 그라디언트 HTML 템플릿 적용.
5. **로깅 및 디버깅 편의성 개선**: SysLog 기반 구조에서 콘솔(`stderr`) 로거의 기본 통합 및 상세 Exception Traceback 지원.

## 🛠️ 3. 상세 처리 내용 및 모듈별 리팩토링 명세

### 3.1 선언형 설정 관리 (`config.py`)
기존 `_get_env()` 함수 and 수동 타입 캐스팅 로직을 제거하고, `pydantic_settings.BaseSettings`를 상속하는 `AppSettings`를 선언했습니다.

* **Pydantic Settings 도입**: `GEMINI_MODELS`, `SMTP_PORT` 등 스네이크 케이스와 대문자 환경 변수명을 `Field(validation_alias="...")` 옵션으로 유연하게 매핑하였으며, 타입 캐스팅 실패 시 Pydantic 내장 검증 예외가 명확하게 발생하도록 변경했습니다.
* **하위 호환성 호환 레이어 설계**:
  * 기존 비즈니스 로직에서 중첩 구조(`config.smtp.host`)를 직접 참조하고 있으므로, `AppSettings` 내부에 `smtp` 프록시 프로퍼티를 구현하여 기존 구조체를 반환하게 처리함으로써 기존 모듈들의 코드를 완벽히 유지했습니다.
  ```python
  @property
  def smtp(self):
      return SmtpConfig(
          host=self.smtp_host,
          port=self.smtp_port,
          user=self.smtp_user,
          password=self.smtp_password,
          mail_from=self.mail_from,
          mail_to=self.mail_to,
      )
  ```
  * `load_config(args)` 래퍼 함수를 제공하여 CLI 인자(`--log-dir`, `--dry-run`, `--log-file`)가 주입될 경우 `AppSettings` 인스턴스의 필드를 유연하게 덮어쓰도록(override) 조치했습니다.

### 3.2 Pydantic Structured Generation 연동 (`report.py`)
기존 딕셔너리 기반의 `json_schema` 대신 Pydantic `BaseModel`을 상속하는 구체적인 스키마를 선언하고, `google-genai` SDK of `response_schema`에 할당했습니다.

* **스키마 설계**:
  * `upsum`: `UpdateReportSchema`를 정의하여 `title`, `reboot_required`, `summary`, `analysis`, `near_future`, `actions` 추출.
  * `sumuplogs`: `LogSummaryReportSchema`와 개별 주요 에러를 분석하기 위한 중첩 스키마 `KeyIssueSchema`를 구성하여 구조화된 계층 로그 보고서 생성.
* **방어적 파라미터 파싱 (Defensive Programming)**:
  * `config.gemini_models`가 문자열(`str`) 형식으로 들어오거나, `models` 매개변수가 문자열로 입력될 때, 루프를 돌면서 단일 문자(예: `"g"`)로 호출되는 SDK 404 예외 버그를 방지하기 위해 `report.py` 내부에서 타입 검사를 수행하고 `split(",")`으로 자동 치환하는 안전 로직을 구현했습니다.
* **이중 예외 처리 (Fallback Parser)**:
  * Pydantic `model_validate_json()`이 실패할 경우, 코드 펜스(```json)를 정규식으로 다듬어 파싱하는 원시 JSON 폴백 파서(`parse_json_response`)를 이중 안전장치로 호출하도록 구현했습니다.

### 3.3 Jinja2 기반 Styled HTML 이메일 템플릿 도입 (`email_sender.py`)
단순 마크다운 변환기를 넘어, Jinja2 `Template` 엔진과 고급 CSS 레이아웃을 주입한 완성도 높은 보고서 템플릿을 개발했습니다.

* **도메인별 맞춤형 테마**:
  * **`upsum` (시스템 업데이트)**: 안정적이고 신뢰감을 주는 **Deep Blue-gradient (#1f2328 ~ #2f363d)** 색상의 메인 헤더 레이아웃 적용.
  * **`sumuplogs` (시스템 에러/경고 요약)**: 문제 상황과 경각심을 가시화하기 위해 **Dark Red-gradient (#241416 ~ #3e1b1e)** 및 적색 코드 포커스 CSS 스타일링 적용.
* **마크다운 렌더링 스타일 보강**: 인라인 코드 블럭(`<code>`) 스타일, 볼드체 강조, 인용문 블록(`<blockquote>`) 등의 컴포넌트 CSS 속성을 명시적으로 이식하여 모바일 및 PC 이메일 클라이언트에서 균일한 화면으로 렌더링되게 했습니다.

### 3.4 콘솔 로깅 및 트레이스백 고도화
* **콘솔 핸들러 기본 활성화 (`config.py`)**: `/dev/log`를 주소로 하는 `SysLogHandler`가 syslog 환경에 의존해 터미널에 에러 로그를 남기지 않던 제약을 해소하기 위해, `sys.stderr`를 대상으로 하는 `StreamHandler`를 기본 장착했습니다. 이로써 콘솔 수동 실행 시 에러 추적과 크론(cron) 로그 리다이렉션이 비약적으로 수월해졌습니다.
* **상세 Traceback 디버깅 (`__main__.py`)**: 예기치 않은 최상위 예외 발생 시 디버깅을 위해 상세 콜스택을 로깅하도록 `logger.error("...", exc_info=True)` 설정을 보강했습니다.
